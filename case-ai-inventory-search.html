Inventory Scraper & Data Distribution Workflow

A Make-based workflow that used Firecrawl, code modules, JSON extraction, and Google Sheets to turn public vehicle pages into structured inventory data for downstream vendors and marketplaces.

Context

Inventory data is often handled through legacy systems, FTP feeds, vendor-managed exports, or API access that can require approval and setup. This workflow started from a practical question: if the vehicle data is already visible on public inventory pages, can that become a usable feed-like data source?

Problem

The workflow needed to create an alternate path to structured inventory data without waiting on an FTP feed or vendor API process. It also needed to handle daily inventory changes, filter out irrelevant site links, extract valid vehicle data, and prepare rows that could be shared with other vendors or marketplaces.

Constraints

  • Needed to run on a schedule
  • Needed to clear stale rows before each run
  • Needed to filter out irrelevant site links
  • Needed to extract structured JSON from inventory pages
  • Needed to validate VINs before writing rows
  • Needed to capture photo links along with core vehicle details
  • Needed to support daily inventory changes and downstream data distribution

Workflow architecture

The workflow runs daily, refreshes the working sheet, extracts current inventory data from public vehicle pages, and turns it into a feed-like output.

Scheduled run

Runs daily because inventory changes constantly and stale vehicle data loses value quickly.

Clear Sheet

Refreshes the working sheet by removing old rows before the new inventory run starts.

Firecrawl map

Gets all links from a predetermined inventory listing page so the workflow can discover current vehicle pages.

Filter URLs

Removes navigation, internal site, external, and irrelevant links, keeping only the inventory URLs needed for extraction.

Iterator

Runs through the filtered URL list one page at a time so the workflow can process every vehicle page consistently.

JSON extraction

Uses JavaScript/code steps to pull the exact vehicle data needed from each page and structure it as JSON.

VIN check

Confirms that each extracted unit includes a valid VIN before it is written into the dataset.

Sheet rows

Loads each car into Google Sheets one row at a time, with vehicle attributes organized into columns.

Distribution

Makes the refreshed data feed available for the places it needs to go, including marketplaces and vendor workflows.

My role

Designed the Make workflow structure, used Firecrawl's API for site mapping, created code steps to clean and filter URLs, connected the iterator and JSON extraction flow, validated VIN presence, and structured the Google Sheet output so the data could be used like an operational inventory feed.

Outcome / value

  • Created a practical ingestion path from dealer website pages to structured spreadsheet rows
  • Reduced irrelevant URL noise before extraction
  • Captured valid vehicle rows with VINs and photo links
  • Created a feed-like output that could support downstream vendors, marketplaces, or internal workflows
  • Reduced dependency on slower FTP/API access paths for prototyping and operational testing

What I learned

Inventory automation starts with access to reliable data. Site mapping, URL cleanup, JSON structure, VIN validation, daily scheduling, and clean spreadsheet outputs mattered more than a polished front-end concept.
