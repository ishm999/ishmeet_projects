Inventory Scraper & Data Distribution Workflow

A Make workflow that used Firecrawl, code modules, JSON extraction, and Google Sheets to turn public vehicle pages into feed-like inventory data.

Context

Inventory data often sits behind legacy feeds, vendor exports, or API approvals. This workflow used public vehicle pages as a practical feed-like source.

Problem

Create structured inventory rows without waiting on FTP/API access, while handling daily changes and filtering irrelevant links.

Constraints

  • Daily scheduled refresh
  • Filter irrelevant links
  • Extract JSON from inventory pages
  • Validate VINs and capture photo links
  • Output rows for distribution

Workflow architecture

Runs daily, refreshes the Sheet, extracts current vehicle data, validates VINs, and outputs a feed-like table.

Scheduled run

Runs daily because inventory changes constantly and stale vehicle data loses value quickly.

Clear Sheet

Refreshes the working sheet by removing old rows before the new inventory run starts.

Firecrawl map

Gets all links from a predetermined inventory listing page so the workflow can discover current vehicle pages.

Filter URLs

Removes navigation, internal site, external, and irrelevant links, keeping only the inventory URLs needed for extraction.

Iterator

Runs through the filtered URL list one page at a time so the workflow can process every vehicle page consistently.

JSON extraction

Uses JavaScript/code steps to pull the exact vehicle data needed from each page and structure it as JSON.

VIN check

Confirms that each extracted unit includes a valid VIN before it is written into the dataset.

Sheet rows

Loads each car into Google Sheets one row at a time, with vehicle attributes organized into columns.

Distribution

Makes the refreshed data feed available for the places it needs to go, including marketplaces and vendor workflows.

My role

Designed the Make workflow, used Firecrawl for mapping, wrote URL filtering/code steps, validated VINs, and structured the Google Sheet output.

Outcome / value

  • Turned dealer pages into structured Sheet rows
  • Reduced irrelevant URL noise before extraction
  • Captured VINs, photos, and core attributes
  • Created a feed-like output for vendors, marketplaces, or internal workflows
  • Reduced dependency on slow feed/API access paths

What I learned

The hard part was reliable data access: mapping, URL cleanup, JSON structure, VIN checks, scheduling, and clean outputs.
